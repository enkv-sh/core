# Native generator host

This module admits and runs installed native generators through the public
`generator-wire-v3` family protocol. Core supplies admitted actions. Crypto owns
private result intake. The host checks the captured executable and complete build facts,
correlates each exchange and joins the child before disposal.

`NewInstallation` checks the declared generator wire and measured artifact
facts. Plugin names, module paths and semantic contract identities are bounded
data. The installation coordinator owns source authentication and local trust.
Metadata alone supplies no effect permission.

`PublicValidator` normalizes settings, validates exact canonical intent and
checks retirement compatibility with the same captured build. These passive
calls receive no private environment or value payload. The plugin owns settings
grammar, defaults, resource interpretation and compatibility decisions.

Before each invocation, the host copies the executable into a fresh private
stage, authenticates exact bytes and checks actual build information. It starts
that copy with an empty environment and fixed pipe descriptors. A finite host
context covers the complete invocation, including result intake and child join.
The host preserves the admitted request's exact bytes and deadline.

After effect admission and handshake, the host captures only environment names
from the declared credential route. Absence and a present empty value remain
distinct. The complete private encoding fits 65,536 bytes. Provider credential
syntax and SDK discovery belong to the plugin. `InvocationCredentials` retains
one capture per exact route for the invocation and clears its owned bytes after
all sessions join. A later invocation can capture rotated credentials; this
supplies no retry or resend permission.

`NewRetainedInstallation` checks the same exact family construction for accepted
work. Core must match the complete original executor and credential-route tuple.
Missing or changed original support refuses without current-selection fallback.
A NEW retirement Duty uses the separately admitted current build's passive
compatibility result for the original resource contract, target and data, then
fixes that execution support. Equal local names or intent bytes do not establish
resource compatibility. Lifecycle mode `none` supplies no external retirement
resource; mode `managed` requires the typed resource facts.
Native plugins are trusted code; this process boundary is not OS confinement.

Acquisition, close and cleanup failures retain their causes. Telemetry uses the
shared application setup and closed failure fields. Public records and telemetry
contain no credential values. See the
[telemetry guide](../../tests/examples/telemetry/README.md).
